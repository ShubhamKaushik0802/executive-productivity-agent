## Operating assumptions

1. The user is Arjun Malhotra, and the agent is built for him.
2. The date selected in the UI is the brief's “today”.
3. Daily status is evaluated at the end of the selected day unless the task has a more precise completion/readiness time.
4. A missing/uncertain owner is **UNKNOWN**, not inferred.
5. A later explicit commitment can supersede an earlier deadline while the history remains visible.
6. Calendar entries are evidence for timing; they are not independently duplicated into tasks.
7. Voice notes are treated as Arjun's own reminders and commitments.
8. The prototype uses no external business information.

## Non-assumptions

The prototype does **not** assume that Facilities owns the Mumbai lease simply because the data says the process “typically” sits there. That is specifically treated as unconfirmed.
